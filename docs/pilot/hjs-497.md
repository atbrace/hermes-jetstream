# hjs-497 — receipt inspection without a nats CLI (pilot friction)

## Reproduction

Peer pilots run the broker in a container (stock `nats:2-alpine`, per README quickstart).
That image ships **no `nats` CLI**, and the JetStream monitor endpoint (`$JS.API.INFO` /
`/jsz`) returns account/stream **aggregates only** — per-stream and per-consumer detail
sub-requests 404 on the monitor surface. So when a wake looks missing, the pilot has no
way to answer "is the event in the stream? has the consumer acked it?" from outside.

## Exact gaps found in this repo (at ba047ef)

1. `README.md:34,43`, `docs/CONFIG-REFERENCE.md:67`, `examples/README.md:7,24` all use
   the `nats` CLI (`nats stream add`, `nats pub`, `nats watch`) with **no mention of how
   to get the CLI** when the broker container has none and the host has none installed.
2. The "Watchability" section covers the plugin-side surfaces (`jetstream_status`,
   `gateway_state.json` metrics, heartbeat) but has no server-side receipt-inspection
   recipe (`nats stream info` / `consumer info` / last-msg read).
3. No `docker run natsio/nats-box` (or equivalent) sidecar snippet anywhere; docs
   otherwise carry a `docker run` for the server itself (README:38), so a CLI sidecar
   is the obvious missing twin of it.
4. The ack/dedupe truth the plugin keeps (`wake-claims.db`, dedupe key
   `<stream>:<consumer>:<stream_seq>`) is only described in code (`wake.py`,
   `ledger.py`), never as an inspection surface.

Verdict: **gap exists — reproduced.**

## Fix shipped (docs rung)

- `docs/CONFIG-REFERENCE.md`: new "Inspecting receipts without a nats CLI on the broker"
  section — nats-box sidecar `docker run` wired to the same auth/TLS posture as the
  settings table, plus the exact receipt recipe against this plugin's naming
  (stream = `stream` setting, default `hermes`; wake durable/queue = `jetstream-<route>`;
  ledger dedupe key).
- `examples/nats-box-receipts.md`: standalone copy-paste version of the same flow.
- No plugin code: the plugin never touches the CLI; the server-side view is pure
  `nats` CLI against existing streams/consumers.
